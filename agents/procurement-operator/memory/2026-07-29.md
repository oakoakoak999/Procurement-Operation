### Failures — 4, all transient, all cleared

PSUV ×2, PUBN, PSNK, PLPN2, PKAN (one date each across separate passes). One was
an explicit Google `502 Server Error`; the rest exited without writing a result
file. Every one succeeded on re-run with no code change, which is the whole
reason FAILED dates stay in the state file rather than being dropped — re-running
the identical command retries exactly those dates and nothing else.

### Folder structure change

Uploads now land in `year / NN.Month / DD/MM/YYYY / vendor`. The numeric month
prefix is zero-padded because Drive sorts names as text: bare names listed
alphabetically (April, August, December…), and `1.January` would sort after
`10.October`. `tools/rename-month-folders.mjs` migrated 19 pre-existing folders
in place via `files.update`, which preserves the folder ID — children are never
moved or re-uploaded and share links keep working. That migration touched live
daily-pipeline folders (PPCH, PUTD), not only backfill output.

### Performance work

Upload was 89% of a date's runtime at 3.2 s/file. Parallelising files (6 wide),
then vendor folders (2 per lane), then dates (3 lanes) brought it to ~0.43 s/file
and ~0.70 min/date. Measurement corrected two of my own assumptions: raising
Drive concurrency from 24 to 36 in-flight changed nothing (so Drive was never the
constraint), and the real floor is the per-date print stage — roughly 40 s of
browser launch, login, nav and filters that no upload concurrency touches.
